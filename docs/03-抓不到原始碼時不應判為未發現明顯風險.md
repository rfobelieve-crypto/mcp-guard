# 抓不到原始碼時，不應該判成「未發現明顯風險」

> 第三篇筆記。與第二篇一樣，這不是外部事件，而是**這個工具自己說了超出事實的話**。
>
> 差別在於這一篇比較嚴重：第二篇是措辭不精確，這一篇是**把「沒看到」講成「看過了沒事」**。
>
> **本文只提出證據與選項，沒有修改 `checks.py` 或 `fetch.py`。** 判定邏輯的決定權在引擎維護者。

---

## 摘要

2026-08-07 21:45 那次每日重掃，`medplum/medplum` 從 🟡 需人工複核 變成 🟢 未發現明顯風險。

看起來像好消息，其實不是。翻轉的原因不是那個 HIGH 被澄清了，而是**這次一個檔案都沒抓到**：

| 欄位 | 08-07 01:06 | 08-07 21:45 |
|---|---|---|
| `files` | **443** | **0** |
| `high` | 1 | 0 |
| `med` | 1 | 0 |
| `profile` | `devtool`（開發框架／工具鏈） | `general`（未能明確判定） |
| `top` | npm 套件標示的倉庫與實際來源不一致 | — |
| `verdict` | 🟡 需人工複核 | 🟢 未發現明顯風險 |
| `why` | 有 1 項高風險項目… | **常見風險樣式均未命中**；仍建議只給最小權限憑證。 |

那句 `why` 是問題的核心。**「常見風險樣式均未命中」在零個檔案的情況下是假話**——
沒有任何樣式被比對過，因為根本沒有東西可以比對。

同時消失的還有這些原本存在的事實陳述：

```
- npm 套件標示的倉庫與實際來源不一致      HIGH   ← 撤回了一項高風險指控
- 會連往 82 個外部主機                    MEDIUM
- 會讀寫本機檔案（符合宣稱用途）           LOW
- 會讀取環境變數（符合宣稱用途）           LOW
- 已掃描 2 個代理指令檔                    INFO  → 變成「沒有代理指令檔」
```

最後一項特別值得注意：`已掃描 2 個代理指令檔` 變成 `沒有代理指令檔`。
**這是把「我沒去看」寫成「那裡沒有」。**

---

## 一、不是單一個案，是系統性的

在 2026-08-07 21:45 的資料中，`files == 0` 的專案有 **14 個**，
而且**這 14 個全部都被判為 🟢 未發現明顯風險**——相關性 100%。

```
🟢 ruvnet/ruflo              🟢 MystenLabs/sui
🟢 tldraw/tldraw             🟢 medplum/medplum      ← 新加入
🟢 PostHog/posthog           🟢 dgunning/edgartools
🟢 Skyvern-AI/skyvern        🟢 kubeshop/testkube
🟢 screenpipe/screenpipe     🟢 nrwl/nx-console
🟢 googleapis/mcp-toolbox    🟢 sceneview/sceneview
🟢 coder/coder               🟢 nirholas/three.ws
```

這份名單的共通點很明顯：**多數是大型 monorepo**。
`tldraw`、`PostHog`、`coder`、`MystenLabs/sui`、`nx-console`、`testkube`
都不是小專案。（`nirholas/three.ws`、`dgunning/edgartools` 相對小，
表示成因可能不只「體積過大」一種，值得一併查。）

跨四次重掃的觀察：

| 重掃 | `files == 0` 的專案數 | `medplum` 的 `files` |
|---|---|---|
| 2026-08-04 22:17 | 13 | 443 |
| 2026-08-05 22:18 | 13 | 443 |
| 2026-08-07 01:06 | 13 | 443 |
| 2026-08-07 21:45 | **14** | **0** |

13 個是穩定的，`medplum` 是新加入的——所以這不是隨機抖動，比較像是
**專案大小跨過了某個門檻**（壓縮檔大小上限、解壓縮筆數上限、或抓取逾時），
而 `medplum` 剛好在這一天跨過去。

## 二、為什麼這比漏報更值得處理

`/trust` 那一頁明說：對真實專案的不實指控，傷害不比漏報小。
這一條是它的鏡像，而且更難被發現：

- **漏報**：使用者裝了有問題的東西。壞，但至少沒有人騙他。
- **這一條**：工具主動說「未發現明顯風險」「常見風險樣式均未命中」，
  使用者因此**降低戒心**。他不是沒有得到資訊，他是得到了錯誤的保證。

而且這 14 個全是知名大專案，正好是使用者最可能相信、也最可能實際安裝的那一批。
一個把 `PostHog`、`tldraw`、`coder` 全部蓋上綠章、卻其實一行程式碼都沒讀過的稽核工具，
它的綠章在這些條目上是沒有意義的。

還有一層：`medplum` 這次**撤回了一項 HIGH**（npm 套件標示的倉庫與實際來源不一致）。
昨天說有問題、今天說沒問題，中間專案本身什麼都沒變——變的是我們這邊抓不抓得到東西。
一個結論會因為自己的抓取狀況而反覆橫跳的工具，很難主張自己的證據是可複現的。

## 三、影響範圍（不誇大）

- **178 個專案中有 14 個受影響**，約 8%。
- 這 14 個的 🟢 **不代表它們真的有問題**——它們很可能確實沒問題。
  問題在於**我們沒有資格這樣說**，因為我們沒看。
- 其餘 164 個專案的判定不受影響。
- 首頁的即時查詢（`/api/scan`）走的是同一套抓取邏輯，
  所以使用者現場查這些大專案時，也會拿到同樣沒有根據的 🟢。

## 四、三種修法與取捨

### 選項 A：新增「無法完整稽核」這個結論狀態（建議）

`files == 0`（或低於某個下限）時，不要落到 🟢，而是給一個獨立的結論：

```
⚪ 無法完整稽核
這個專案的原始碼這次沒有抓取成功（可能是體積過大或連線逾時），
所以下面只有身分與中繼資料層面的檢查結果。
「沒有命中風險樣式」在這裡不成立——我們沒有讀到程式碼。
```

- ✅ 陳述正確，而且把「不知道」與「沒事」分開，這正是這個產品的立場
- ✅ 使用者知道要自己補做什麼
- ⚠️ 需要新增一個結論狀態，前端的顏色／篩選／統計都要跟著調整
- ⚠️ 首頁「🟢 N 個」的數字會下降，看起來像退步，其實是誠實化

### 選項 B：維持 🟢，但把 `why` 改成不撒謊的措辭

- ✅ 改動最小，不動結論狀態
- ❌ **沒有解決核心問題**——綠章還在，使用者只看顏色不看小字

### 選項 C：先修抓取，不動判定

提高壓縮檔大小上限／逾時，或改成只抓需要的子路徑而不是整包。

- ✅ 治本，14 個裡多數可能因此恢復正常
- ❌ **無法治全部**——一定會有更大的專案存在，門檻永遠會被跨過。
  沒有配套的話，下一個 `medplum` 只是時間問題。
- 💡 與 A 併用最好：A 是安全網，C 讓安全網少被用到

### 附帶建議

不論選哪個，`已掃描 N 個代理指令檔` 在抓取失敗時**不應該退化成
`沒有代理指令檔`**。那兩句話的意思完全不同，而且後者是斷言。

---

## 五、為什麼這份文件沒有附上修改

`checks.py` 的判定邏輯與 `fetch.py` 的抓取策略都在
`UX-TASK-BRIEF.md` 第 0 節列為**絕對不要動的部分**。
而且上面三個選項牽涉產品判斷（要不要新增結論狀態、首頁數字要不要因此變難看），
那是引擎維護者的決定。

順帶一提，這與先前 `gh_json_ex()` 的修法是同一個原則：
**查不到就說查不到，不要在沒有事實的情況下產生結論。**
那次修的是身分查詢（403 被當成 404，於是憑空指控專案不存在），
這次是同一個病灶的另一面——抓取失敗被當成「掃過了，很乾淨」。
一個往壞的方向捏造，一個往好的方向捏造，成因相同。

## 六、自己複現

```bash
# 這次重掃有幾個專案一個檔案都沒抓到，它們的結論是什麼
python3 -c "
import json
d=json.load(open('reports/data.json'))
z=[p for p in d['projects'] if p.get('files',0)==0]
print(f'files=0 共 {len(z)} 個')
for p in z: print(' ', p['verdict'][:2], p['slug'], '|', p['why'][:40])
"

# medplum 這一次與上一次的差異
git show HEAD~1:reports/data.json > /tmp/prev.json
python3 -c "
import json
a=json.load(open('/tmp/prev.json')); b=json.load(open('reports/data.json'))
g=lambda d: next(p for p in d['projects'] if p['slug']=='medplum/medplum')
for k in ('files','high','med','profile','verdict','why'):
    print(f'{k:9} {g(a).get(k)}  →  {g(b).get(k)}')
"
```

---

*發現時間：2026-08-08 01:39 UTC，於例行的六小時巡檢中合併每日重掃時。*
*發現的方式是比對「判定翻轉」——如果只看總數（178 個、🟢 111 個），
這次重掃看起來只是變好了一點。*
